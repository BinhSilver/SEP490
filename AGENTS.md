# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project overview

J-LAS (Japanese Learning & Assessment System) is a Spring Boot 4 / Java 21 monolith with a server-rendered
Thymeleaf + vanilla-JS frontend, backed by MySQL. It's a graduation project supporting personalized Japanese
learning: JLPT-oriented adaptive assessment ("Smart Test"), generated learning paths, dictionary/vocabulary,
flashcards (incl. speed-recall), shadowing practice, AI conversation ("kaiwa"), mini-games, missions, content
moderation, and notifications.

## Commands

### Build & run

```bash
./mvnw spring-boot:run       # run the app (http://localhost:8080), Git Bash/Linux/macOS
mvnw.cmd spring-boot:run     # Windows
./mvnw clean package         # build the jar (target/)
```

Requires a local MySQL database and `src/main/resources/application-local.yaml` (gitignored) with
`spring.datasource.url/username/password` — `application.yaml` always pulls in the `local` profile.

### Backend tests (JUnit, Maven)

```bash
./mvnw test                                   # full suite, runs against in-memory H2 (no MySQL needed)
./mvnw test -Dtest=LearningPathApiTest         # single test class
./mvnw test -Dtest=LearningPathApiTest#create  # single test method
```

Tests never hit MySQL: `src/test/resources/application.yaml` / `application-test.yaml` override the
datasource to H2 (`MODE=MySQL`, `ddl-auto: create-drop`) so `mvn test` works on any machine.

### Frontend tests (plain Node, no build step)

There is no `package.json`/npm pipeline — static JS under `src/main/resources/static/**` is tested directly
with Node's built-in test runner:

```bash
node --test src/test/frontend/*.test.cjs
node --test scripts/speed-recall-rules.test.mjs
node --test src/test/js/personalized-path.test.cjs
```

### Database

- Schema lives in [jlas_schema.sql](jlas_schema.sql) at the repo root — edit it **directly** (not via a
  migration) and tag the change with a `[JLAS-XXXX]` ticket comment; see `docs/rules-and-business-logic.md` §4.
- `sql/migrations/NNN_*.sql` is only for schema changes still landing incrementally in a live DB.
- `spring.jpa.hibernate.ddl-auto=validate` in production/dev — every `@Entity` must already have a matching
  table/column in the schema before the app will start.
- Seed data is kept in separate files under `sql/seeds/`, never mixed into `jlas_schema.sql`. The core content seed
  `sql/seeds/seed_data_jlas.sql` is GENERATED by `tools/generate_seed.py` from `data/seed_jlas/` (needs
  `pip install openpyxl`) — never edit it by hand; change the script or `data/seed_jlas/phan_sua_tay.json` and
  regenerate (output is byte-for-byte deterministic). `PUBLISH_JLPT_N4_N1` at the top of the script decides whether
  N4–N1 is PUBLISHED or DRAFT (N3–N1 content is AI-written, not yet reviewed). Old versions are archived in
  `sql/seeds/_cu/` (do not use).
- Seed run order: `jlas_schema.sql` → migrations `sql/migrations/018_content_source.sql`,
  `sql/jlas_migrations_all.sql`, `sql/migrations/019_situation_tag_ba.sql`,
  `sql/migrations/020_align_checks_credit_reference.sql` (018/019/020 only needed on a DB created from an older schema;
  all re-runnable) → `sql/seeds/seed_data_jlas.sql` → other seeds (`sql/seeds/jlas_seed_all.sql`,
  `sql/seeds/questionbank.sql`, `sql/seeds/ai_call_scoring_rules.sql` …) → `sql/seeds/demo_content_creator.sql`
  (dev/demo only) → `sql/seeds/seed_data_vnjpclub.sql` (last).

## Architecture

### Vertical-slice modules, not horizontal layers

`src/main/java/com/jlas/<module>/` — each business module (`assessment`, `learning`, `dictionary`,
`flashcard`, `game`, `kaiwa`, `mission`, `moderation`, `notification`, `shadowing`, `auth`) is a self-contained
vertical slice with its own `controller/ dto/ entity/ enums/ mapper/ repository/ service/ service/impl/
util/ validation/` subpackages, rather than one global `controller`/`service`/`repository` package for the
whole app. `common/` holds cross-cutting pieces (`ApiException`, `ErrorCode`, `GlobalApiExceptionHandler`,
domain events); `config/` holds app-wide `@Configuration` (`SecurityConfig`, `WebMvcConfig`, `AuthProperties`).

The two modules under active development are **`assessment`** (Smart Test — adaptive JLPT-level placement
testing) and **`learning`** (Learning Path — generates a day-by-day study plan from Smart Test results and
schedules lessons/quizzes/flashcards). **[docs/rules-and-business-logic.md](docs/rules-and-business-logic.md)**
is the authoritative, continuously-updated spec for these two modules' business rules (adaptive test policy,
weakness aggregation, path scheduling, replan, Gemini narrative integration, quiz/gate rules) — read it before
changing behavior there, since the numeric policy constants (batch sizes, thresholds, quiz limits) are chosen
deliberately and cross-referenced against an approved plan.

### API response convention

All `@RestController` endpoints return `ResponseEntity<ApiResponse<T>>` where `ApiResponse`
([src/main/java/com/jlas/auth/dto/ApiResponse.java](src/main/java/com/jlas/auth/dto/ApiResponse.java)) is the
single shared envelope (`success`, `message`, `data`, `errors`, `code`, `timestamp`) used by every module, not
just `auth`. Business/domain errors are thrown as `ApiException(ErrorCode)` — add new failure cases to
[ErrorCode](src/main/java/com/jlas/common/exception/ErrorCode.java) rather than throwing raw exceptions; the
`@RestControllerAdvice` in `GlobalApiExceptionHandler` converts `ApiException`, validation errors, and
`ResponseStatusException` into that same envelope (with Vietnamese user-facing messages).

### Security

Stateless JWT auth (`JwtAuthenticationFilter`, `SessionCreationPolicy.STATELESS`), configured centrally in
[SecurityConfig](src/main/java/com/jlas/config/SecurityConfig.java) via one `authorizeHttpRequests` chain —
per-module security annotations aren't used, so new public/authenticated routes must be added to that matcher
list. `/admin/moderation.html` and `/api/admin/moderation/**` require `MODERATOR/ADMIN/SUPER_ADMIN`; most
`/api/**` endpoints default to `authenticated()` unless explicitly listed as `permitAll()`.

### Frontend

Server-rendered Thymeleaf templates (`src/main/resources/templates/`) per feature area (`learning/`,
`shadowing/`, `aicall/`, `arena/`, `textbooks/`, `fragments/` for shared layout), paired with plain JS under
`src/main/resources/static/js/pages/` and `static/<module>/js/` (e.g. `static/flashcard/js/speed-recall/`).
No bundler/transpiler — JS is written to run as-is in the browser and is unit-tested with Node's `node:test`
directly against the same files the browser loads.

### Vocabulary normalization

`normalized_expression` / `normalized_reading` columns are always
`katakana → hiragana(NFKC(text))`, keeping `ー` (U+30FC) and `・` (U+30FB) as-is. This rule does **not** apply
to `kanji_reading.reading_text`. Any seed/import script that populates these columns must replicate this exact
normalization (see `docs/rules-and-business-logic.md` §4).

### External integrations (all optional/best-effort, keys via env or `application-local.yaml`)

- **Gemini** — writes narrative explanations of a learner's already-computed path (non-fatal if it fails; it
  never generates quiz questions or decides scoring at runtime).
- **OpenRouter**, **Deepgram** (speech-to-text), **Azure Speech** (pronunciation scoring), **ffmpeg/yt-dlp**
  (shadowing video/audio processing) — each configured under its own top-level key in
  [application.yaml](src/main/resources/application.yaml) with an env-var override and a safe default.
